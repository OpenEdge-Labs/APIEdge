# Changelog

All notable changes to APIEdge are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning: [SemVer](https://semver.org/).

## [Unreleased]

### Security
- T-023 (slice 1): native TLS on the console and gateway listeners closes security finding F-02 (TLS 1.2 minimum, AEAD ciphers, no compression or renegotiation; `Secure` cookies and HSTS follow automatically). Client certificates on the gateway (`APIEDGE_GATEWAY_TLS_CLIENT_AUTH`) are checked by the tenant-scoped `mtls` policy; keystore private keys are stored only AES-256-GCM encrypted and never returned.
- T-018: pre-release security verification (`docs/security-verification.md`). Fixed: forwarded headers were trusted from 127.0.0.1 by default, letting a local process bypass the per-IP sign-in throttle and the gateway's IP-filter and per-address rate limits; each listener now trusts only its configured proxies (new `APIEDGE_TRUSTED_PROXIES` for the console, default `127.0.0.1`; the gateway only `APIEDGE_GATEWAY_TRUSTED_PROXIES`). Added an access-control matrix test over every admin operation, a DAST smoke pass (`scripts/dast-smoke.py`), an OWASP ZAP baseline scan of console and gateway and a Grype scan of both container images in CI, with a reviewed, expiring allowlist enforced by `scripts/scan-gate.py`; 18 unfixed High CVEs in Debian base-image packages are accepted there with a review date. Responses now carry `Cross-Origin-Embedder-Policy: require-corp`.
- T-012: captured traffic is stored only AES-256-GCM encrypted (bound to tenant and capture), masked by default on every read path, retention-limited; unmasked views, HAR exports and replays are audit-logged; replay only reaches the API's configured upstreams through the SSRF guard.
- T-008: gateway policies fail closed (unusable configuration answers 503, policy errors 500); policy secrets encrypted at rest and write-only; JWT algorithm-confusion, `none` and weak-key protection; JWKS fetched only through the SSRF guard.
- T-005: fixed the tenant filter being silently skipped for a session factory created at the memory address of a garbage-collected one (install guard relied on `event.contains`, which is keyed by object id); sessions from such a factory were not tenant-filtered. Regression test added.
- T-002: OWASP baseline: security headers and strict CSP, CORS allow-list (closed by default), request body-size limit (413), CSRF protection (double-submit cookie plus Origin check) for cookie-authenticated requests, global error handler without stack traces, 422 responses that never echo input, structured JSON logging with secret masking and request ids, AES-256-GCM secrets encryption helper with key rotation (`pycryptodome`), SSRF guard for upstream URLs, `docs/SECURITY.md` with the OWASP mapping, CodeQL in CI. A CodeQL finding is accepted only with both an inline `codeql[<rule id>]` justification and a row in the `docs/SECURITY.md` "Accepted findings" table, enforced by `scripts/codeql-gate.py`.

### Changed
- T-003: the password policy now also rejects passwords that contain the username or are common, and caps length at 128.

### Fixed
- Analytics integration tests query an explicit time window, so traffic in the first second of a minute can no longer be missed (timing flake on Windows CI).
- T-007: the lock generator now carries patch-level `python_full_version` markers from dependency metadata; `async-timeout` is installed for `python_full_version < "3.11.3"` (as `redis` requires) instead of only below 3.11, so `redis.asyncio` works on Python 3.11.0-3.11.2.
- T-001/T-019: lock files now carry per-target PEP 508 environment markers and are verified on every platform x Python 3.10-3.12 target (fixes developer installs on Python 3.11 and 3.12).

### Added
- T-023 (slice 1): TLS and client certificates. New settings `APIEDGE_TLS_CERT_FILE`, `APIEDGE_TLS_KEY_FILE`, `APIEDGE_TLS_KEY_PASSWORD`, `APIEDGE_TLS_MIN_VERSION`, `APIEDGE_TLS_CIPHERS`, `APIEDGE_GATEWAY_TLS_CERT_FILE`, `APIEDGE_GATEWAY_TLS_KEY_FILE`, `APIEDGE_GATEWAY_TLS_KEY_PASSWORD`, `APIEDGE_GATEWAY_TLS_CLIENT_AUTH`, `APIEDGE_GATEWAY_TLS_CLIENT_CA_FILE`, `APIEDGE_GATEWAY_CLIENT_CERT_HEADER`; command `apiedge tls self-signed`. Tenant truststores and keystores (admin API `/api/v1/tenants/{id}/tls/truststores` and `/keystores`, permissions `tls:read` / `tls:manage`, migration 0008, console page TLS & certificates). New `mtls` gateway policy (client certificate issued by a tenant truststore, subject and fingerprint allow-lists, subject forwarded upstream, consumer `cert:<name>` in analytics). Pure-Python X.509 parsing and validation on pycryptodome, no new dependency (ADR 0013).
- T-017: complete documentation set, built as an offline MkDocs site (`mkdocs.yml`, `mkdocs build --strict` in CI, shipped as `apiedge-<version>-docs.zip` in release builds): documentation home, Installation Guide (renumbered sections, docs bundle), Upgrade notes, Administrator Guide (overview, configuration, access control, new operations page: service, TLS behind a reverse proxy, backup and restore, secrets key, logs, monitoring, disk and memory budget, scaling), User Guide (overview with a first-API tutorial, low-code status page marking T-009/T-010/T-011/T-022 as upcoming), Admin API guide, Troubleshooting, ADR index and ADR 0012. Admin API reference generated from the application by `scripts/export-openapi.py` (`docs/api/openapi.json` and `docs/api/reference.md`; `--check` in CI and tests). Every OpenAPI operation now carries its RBAC requirement as `x-apiedge-access`. Tests check that every setting is documented, that documented `APIEDGE_*` names exist, that relative links resolve and that every page is in the site navigation. New docs-only tooling lock `requirements/docs.lock` (mkdocs 1.6.1, BSD-2-Clause, separate venv; pip-audit and license gate in CI).
- T-016: release packaging. `scripts/build-release.py` builds the wheel (console included, contents checked), one-click installer zips for Windows, macOS and Linux, a CycloneDX 1.5 SBOM, the Helm chart and `SHA256SUMS`; `.github/workflows/release.yml` builds them on `v*` tags (and on packaging changes), installs each bundle unattended with a health check on all three OSs, smoke-tests the wheel, builds the linux/amd64 + linux/arm64 image and tests `docker compose` (APIEdge, PostgreSQL 17, Valkey) including a sign-in. GPG signing and draft-release publishing are opt-in and off until configured. New: `packaging/docker/` (Dockerfile, entry point), `docker-compose.yml`, `packaging/helm/apiedge`, `docs/releasing.md`, ADR 0011; Installation Guide sections for pip, Docker, Helm and verifying downloads.
- T-020: feature parity matrix `docs/FEATURE_MATRIX.md`: 103 capabilities in 11 areas, each with the reference gateways that offer it and the APIEdge status (29 done, 11 partial, 58 planned, 5 proposed) and task; gaps proposed as VP-003 to VP-007.
- T-012: packet inspector. Opt-in, time-boxed captures per API (optionally one route or consumer) with ring buffer, body cap, bounded memory queue and retention; each exchange records request and response (line, headers, body), timings, upstream and attempts, and the per-policy decision trace. Admin API `/api/v1/tenants/{id}/inspector` (sessions, exchanges with filters, Server-Sent Events live stream, detail, HAR 1.2 export, replay) with `inspector:view` / `inspector:capture` / `inspector:unmask`; console **Packet inspector** page. Gateway trace listeners now receive the final response and may return a body tap. New settings `APIEDGE_INSPECTOR_*`, migration 0007, ADR 0010, [Packet Inspector Guide](docs/user-guide/inspector.md).
- T-008: built-in gateway policies, configured per API as an ordered chain (optionally per route) in the console's form-based **Policies** editor or `PUT .../apis/{id}/policies`: API key authentication (product keys shown once, stored as SHA-256, expiry and revocation, **API keys** panel), JWT validation (HS/RS/PS/ES with algorithm allow-list, PEM key or SSRF-guarded JWKS, `exp`/`nbf`/`iss`/`aud`), rate limits and quotas (per consumer, address or API; Redis or in-process; 429 with `Retry-After` and `RateLimit-*`), header/query/JSON-body transforms, CORS with preflight handling, IP allow/deny lists (CIDR; `X-Forwarded-For` only from `APIEDGE_GATEWAY_TRUSTED_PROXIES`), response cache (safe methods, `Cache-Control` aware, credential-aware, size-capped) and mock responses. Every request carries a per-policy decision trace for the packet inspector. Analytics now attributes traffic to `key:<name>` / `jwt:<subject>` consumers. New permissions `apikey:read` / `apikey:manage`, migration 0006, ADR 0009, [policies guide](docs/user-guide/policies.md).
- T-013: analytics. The gateway measures every API request (status, latency, bytes, route, method, consumer) into per-minute aggregates with latency histograms, flushed to the new `analytics_buckets` table (migration 0005, retention `APIEDGE_ANALYTICS_RETENTION_DAYS`, flush `APIEDGE_ANALYTICS_FLUSH_INTERVAL_SECONDS`). Admin API `GET /api/v1/tenants/{id}/analytics/summary` (requests, error rate, 4xx/5xx, p50/p95/p99 latency, bytes, time series, status codes, top APIs and consumers, time-range/API/product/consumer filters) and `GET .../analytics/export.csv` (audited), both with `analytics:view` tenant-wide or per product. Prometheus endpoint `GET /metrics`, enabled with a bearer token `APIEDGE_METRICS_TOKEN`. Console Analytics page with KPI tiles, traffic chart, drill-down tables and CSV export. Analytics Guide `docs/user-guide/analytics.md` (ADR 0008).
- T-007: gateway runtime. `apiedge run` also serves the data plane on `APIEDGE_GATEWAY_PORT` (default 8081): published APIs at `/<tenant slug><base path>`, route matching with `{name}` parameters and `/*` wildcards (404/405), deprecated APIs flagged with `Deprecation: true`, retired APIs and products answered with 410, smooth weighted round-robin over upstreams, per-API timeouts (504), retries on another upstream (connection failures for all methods, timeouts and 502/503/504 for idempotent methods), verified TLS to upstreams with an optional CA bundle, hop-by-hop header stripping, `X-Forwarded-*` and `X-Request-ID`, a request body limit, and fixed error documents. Configuration hot-reloads without a restart through in-process events, Redis pub/sub (`APIEDGE_REDIS_URL`, optional) and a periodic reload. The SSRF guard is re-applied at every upstream connect (DNS rebinding). The admin API returns `gateway_path`, shown in the console's API list; system settings list the gateway settings. New runtime dependency `redis` (MIT) (ADR 0007).
- T-006: API management inside products. Admin API `/api/v1/tenants/{id}/products/{pid}/apis` (list, create, get, update, lifecycle change, delete) with tenant-wide or product-scoped `api:*` permissions; an API has a base path (unique per tenant, reserved server paths refused), version, timeout, weighted upstreams checked by the SSRF guard, and routes (methods plus a path with `{name}` parameters and a final `/*`, no overlaps); lifecycle draft -> published -> deprecated -> retired (publishing needs an upstream and a route); audit events `api.*`. Products that still contain APIs cannot be deleted. Console: an APIs panel per product with a no-code form editor. Migration 0004 (ADR 0006).
- T-005: product management. Admin API `/api/v1/tenants/{id}/products` (list with lifecycle filter, create, get, update, lifecycle change, delete) with tenant-wide or product-scoped `product:*` permissions, owners chosen from the tenant's users, lifecycle draft -> published -> deprecated -> retired, and audit events. Console Products screen and a product scope for role grants on the Users screen. Migration 0003 adds `products` and `product_owners` and the foreign key from product-scoped role grants to products (ADR 0005).
- T-004: web console admin panel. Sign-in with TOTP step, forced password change on first sign-in, app shell with permission-aware navigation and a tenant selector for SuperAdmins; screens for tenants, users (create, enable/disable, unlock, reset MFA, reset password, delete, role grants), roles and permissions (custom role editor limited to held permissions), audit log (filter, paging, all-tenants view for SuperAdmins), read-only system settings, and My account (password change, MFA set-up and removal). New admin API route `GET /api/v1/system/settings` (SuperAdmins, never returns secrets). Console unit tests run with Node's built-in test runner (`npm test`, also in CI); no new npm dependencies.
- T-003: authentication, multi-tenancy and RBAC core. Admin API `/api/v1`: sign-in with Argon2id passwords, password policy, per-IP throttling and account lockout, 15-minute JWT access tokens (Bearer or HttpOnly cookie) with rotating refresh cookies and reuse detection, forced password change, TOTP MFA; tenants, users, built-in and custom roles, `resource:action` permission catalog, tenant- and product-scoped role grants with anti-escalation rules; tenant-filtered data access in the database layer; audit log with tenant and platform views. New settings `APIEDGE_ACCESS_TOKEN_TTL_SECONDS`, `APIEDGE_REFRESH_TOKEN_TTL_HOURS`, `APIEDGE_LOGIN_*`, `APIEDGE_JWT_SECRET`, `APIEDGE_COOKIE_SECURE`. New dependencies `pyjwt` 2.15.1 and `pyotp` 2.10.0 (MIT).
- T-001: `apiedge` Python package (FastAPI, pydantic-settings, SQLAlchemy 2 + Alembic, SQLite default / PostgreSQL optional), CLI `init | migrate | run | create-admin | version`, `/healthz` and `/readyz` probes, Argon2id-hashed bootstrap SuperAdmin, React + Vite + TypeScript console shell prebuilt into `src/apiedge/static`, ruff / mypy --strict / bandit / pytest / pre-commit config, `.env.example`, GitHub Actions CI (Windows, Linux, macOS x Python 3.10-3.12), architecture docs and ADRs.
- T-019: one-click installers `install.bat` (Windows), `install.command` (macOS) and `install.sh` (Linux) on top of the shared `scripts/install.py`: Python check with guidance, venv, hash-locked install from PyPI (`requirements/*.lock`), migrations, first admin, shortcuts, start at logon, `--unattended`, `--proxy`, `--index-url`, `--uninstall`, install log. Lock tooling (`scripts/update-locks.py`), license gate and `THIRD_PARTY_LICENSES.md` (`scripts/check-licenses.py`), CI installer smoke test on all three OSs.
- Project guide (`docs/PROJECT_GUIDE.md`) and task list (`APIProjectTask.md`).

# ADR 0012: Documentation site and generated Admin API reference

- Status: accepted
- Date: 2026-11-02
- Task: T-017

## Context

T-017 asks for the complete documentation set, published as an MkDocs site that is built in CI
and shipped in the release bundle, including an Admin API reference (OpenAPI plus a rendered
HTML version). Documentation that is written by hand drifts from the code: setting names,
defaults, routes and permissions change task by task.

## Decision

* **MkDocs 1.6.1** (BSD-2-Clause) with its built-in `mkdocs` theme and only Python-Markdown's
  bundled extensions. No third-party theme or plug-in, nothing loaded from a CDN
  (`highlightjs: false`), and `use_directory_urls: false`, so the built site works offline from
  `file://`. MkDocs and its dependencies are pinned with hashes in `requirements/docs.lock`
  (from `requirements/docs.in`, generated by `scripts/update-locks.py`), installed into a
  **separate** virtual environment in CI and release builds only. They are never part of the
  runtime lock or the one-click installer.
* `mkdocs build --strict` with link, anchor and navigation validation set to `warn`: any broken
  internal link, missing anchor or page outside the navigation fails the build.
* **The Admin API reference is generated from the application.** `scripts/export-openapi.py`
  builds the app in production mode and writes `docs/api/openapi.json` and
  `docs/api/reference.md`, which MkDocs renders to static HTML. `--check` fails when the
  committed files differ; CI and the test suite run it.
* Each operation's access requirement is published in the OpenAPI document itself as
  `x-apiedge-access` (`scope` and `permission`), derived from the route's RBAC dependency
  (`apiedge.admin.deps.annotate_access`), so the reference shows the permission each route needs
  without a hand-kept table. A test requires every tenant route to declare a permission.
* Tests also check that every `Settings` field is documented in `.env.example` and the
  configuration guide, that every `APIEDGE_*` name in the docs exists, and that relative links
  in the Markdown files outside the site (README, CHANGELOG) resolve.
* The release workflow builds the site and ships it as `apiedge-<version>-docs.zip`, listed in
  `SHA256SUMS`.

## Consequences

* Documentation changes that break links or the reference fail CI instead of shipping.
* MkDocs 1.6.1 is the latest release but has had no release since August 2024. It is used only
  at build time on trusted, committed input, so the exposure is small; if it becomes
  unmaintained or vulnerable, the Markdown sources stay portable to another generator.
* Search in the built site needs a web server (browsers block the search index on `file://`);
  navigation works offline.
* Links from the site to files outside `docs/` (CHANGELOG, LICENSE) point to the repository
  on GitHub.

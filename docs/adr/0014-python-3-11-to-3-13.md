# ADR 0014: Supported Python range 3.11 to 3.13

- Status: accepted
- Date: 2026-11-05
- Task: T-032

## Context

APIEdge supported CPython 3.10 to 3.12 (ADR 0001, ADR 0002). Python 3.10 reached end of life in
October 2026 and no longer receives security fixes. Holding it back also blocked dependency
security fixes: filelock 4.2.1 (17 advisories in the dev tooling) requires Python 3.11 or newer,
so those advisories had to be accepted as dev-only exceptions. Python 3.13 has been stable for
over two years and every runtime dependency publishes wheels for it. The customer accepted
proposal VP-001 on 2026-11-05.

## Decision

- Supported interpreters are CPython 3.11, 3.12 and 3.13 (`requires-python = ">=3.11,<3.14"`).
- The hash locks are generated for the 15 targets Windows x86_64, Linux x86_64/aarch64 and macOS
  x86_64/arm64 x CPython 3.11, 3.12 and 3.13 (`scripts/update-locks.py`).
- CI tests the matrix of the three OSs x the three Pythons; the release wheel smoke test runs on
  the oldest and newest supported Python.
- The installers (`install.ps1`, `install.sh`, `install.py`) accept only 3.11 to 3.13 and suggest
  3.12 when none is found.
- Code targets Python 3.11 (`ruff target-version = "py311"`, `mypy python_version = "3.11"`), so
  `datetime.UTC` and `tomllib` are used directly.
- The Docker image stays on Python 3.12.

## Consequences

- Hosts with only Python 3.10 must install a newer Python before installing or upgrading
  APIEdge; the installer explains how.
- The 3.10-only backports (`tomli`, `exceptiongroup`, `backports-asyncio-runner`) leave the
  locks, and the dev-only filelock exception list is removed.
- Supporting Python 3.14 later means adding it to `PYTHONS` in `scripts/update-locks.py`, the CI
  matrix and the installers, and raising the upper bound.
